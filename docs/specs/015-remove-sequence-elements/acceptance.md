и scripted model; сетевые вызовы каталога, генератора и TypeSafe не нужны.
Живой диалог проверяет выбор инструмента моделью отдельно от этих проверок.

## 1. Удаление и идентичность

1. Удаление одного среднего, первого и последнего вхождения создаёт ожидаемый
   список. Удаление B/D из `[A, B, C, D, E]` даёт `[A, C, E]`;
   обратный порядок UUID в аргументах даёт тот же результат.
2. Соседний диапазон и несколько несоседних целей удаляются одним действием
   по позициям исходного снимка, без промежуточных вариантов и сдвига целей.
3. Оставшиеся элементы сохраняют относительный порядок, `element_id`,
   полный catalog item и оба mirror flags, включая отличия от `bilateral`.
   `order` равен `1..N-K`, `elements_count` — длине результата.
4. Удаление одного вхождения повторяющегося catalog item сохраняет остальные
   повторы. Удаление зеркального вхождения удаляет его целиком и считается
   одним элементом. Разные вхождения одной позы можно удалить вместе.
5. Новый UUID отличается от родителя, family сохранена, parent указывает
   на выбранный вариант, `operation=remove`, `operation_request` содержит
   полный текущий запрос. `generation_request`, имя, описание и язык сохранены.
6. Родитель и остальные snapshots не меняются. Изменение вложенного catalog
   item нового варианта не меняет исходный snapshot и соседние варианты.
   Старые значения `operation` продолжают десериализоваться.

## 2. Валидация и атомарность

7. Пустой список целей, `null`, неверные типы и невалидные UUID отклоняются
   стандартной валидацией. Повтор UUID даёт `invalid_arguments`.
   Самостоятельный редактор также проверяет пустой список и повторы.
8. Отсутствие полного активного снимка даёт `sequence_not_found`; UUID другого
   варианта, включая сохранённый в истории, — `stale_sequence`.
   При сочетании этих условий соблюдается порядок проверок из README.
9. Неизвестный UUID или смесь известных и неизвестных целей возвращает
   `sequence_element_not_found` без частичного удаления. UUID удалённого
   ранее вхождения не считается допустимым в новом выбранном варианте.
10. Пустой исходный список даёт `empty_sequence`. Удаление единственного
    элемента и всех N элементов даёт `would_empty_sequence`.
    Удаление N-1 при N>=2 успешно оставляет один элемент; tool не выбирает
    сохраняемую позу автоматически и не обрезает набор целей молча.
11. Проверить ошибочное входное `elements_count`: размер определяется списком.
    Из импортированного снимка из 50 элементов допустимо удалить один;
    результат содержит 49 без применения лимита генерации 45.
12. Все ошибки оставляют UUID, историю, исходные элементы и флаг commit
    неизменными; UUID нового варианта и событие commit не создаются.
    Исправленный допустимый вызов в этом запросе может завершиться успешно.
13. Удаление стартовой, второй и завершающей поз не запускает подбор
    или проверку правил генерации. Generator factory, каталог и TypeSafe
    не вызываются; `latest_catalog_items` не читается и не изменяется.

## 3. Agent loop и диалог

14. В настоящем agent/tool loop со scripted model один вызов возвращает
    один `Command`: полный новый snapshot доступен в state, новый UUID активен,
    флаг commit установлен. Компактный результат содержит только envelope
    и `removal` по README; удалённые элементы упорядочены по исходному списку.
15. Следующий вызов модели видит только оставшиеся вхождения в актуальном
    `selected_sequence`. Ограниченная история распознаёт новый tool,
    сохраняет факты удаления и не подменяет выбор старым snapshot/summary.
16. Один набор из нескольких целей расходует одну успешную операцию.
    Второе удаление и любая генерация/замена/обмен/добавление после удаления
    в этом же запросе блокируются, включая вызов с новым UUID.
    Удаление после этих операций также блокируется; новый запрос сбрасывает
    лимит. Generate/Regenerate возвращают `generation_required` для удаления.
17. Несколько tool calls в одном model message отклоняются существующим
    механизмом последовательного исполнения. Ошибка не заявляется успехом,
    идентичный ошибочный вызов автоматически не повторяется.
18. На живой модели проверить русские и английские команды для одной цели,
    списка, диапазона, первой/последней и последних двух поз, а также
    «Можешь удалить…?». В аргументах — UUID актуального снимка;
    повтор одной ссылки сводится к одной цели до вызова tool.
19. Повторяющееся имя, неясное местоимение, отсутствие цели, запрос уменьшить
    размер/длительность без выбора целей требуют уточнения без изменений.
    Позиция за диапазоном не приводит к удалению остальных целей.
    Отсутствие секвенции не приводит к автогенерации.
20. «Удали вторую и четвёртую» выполняется одним удалением.
    «Удали вторую и поменяй первую с третьей» требует выбора одной операции
    без вызовов tools. Гипотетический вопрос только объясняется.
    «Удали все» и удаление единственной позы объясняют запрет пустого результата.
21. После обычного успешного удаления final message пустой. Уточнение,
    ошибка и отдельно запрошенное объяснение отображаются на языке
    пользователя без шаблонного подтверждения или предложения продолжить.

## 4. Прогресс, история, UI и Save

22. Удаление публикует этап `updating_sequence` с заголовком
    `Removing sequence elements...`, правильными request/step/tool IDs
    и summary фактического числа удалённых и оставшихся элементов.
23. Ровно один `sequence_committed` появляется после доступности нового
    снимка в state, с UUID результата. Нет предварительных элементов,
    поэлементного прогресса, поиска, TypeSafe и галереи каталога.
    Ошибка завершает этап с outcome `error`, без commit и новой карточки.
24. UI показывает порядок и зеркальность оставшихся поз. Previous/Next
    и Use this sequence возвращают родителя с исходным составом.
    Удаление из выбранного старого варианта создаёт ветку с правильным parent;
    наличие более нового варианта не меняет источник операции.
25. Rerun не вызывает удаление повторно. Ошибка модели после commit
    сохраняет новый snapshot, активный выбор, карточку и Save.
26. Regenerate результата использует исходный `generation_request`,
    создаёт обычный вариант в той же family с parent результата удаления
    и не повторяет удаление автоматически.
27. В браузере Save результата передаёт новый `info.uuid`, фактический count,
    только оставшиеся catalog UUIDs, непрерывный order и сохранённые flags.
    Два Save одного варианта дают одинаковые UUID и payload;
    Save родителя содержит исходный состав. Для длинных импортированных
    снимков сохраняется проверка диапазона `1..75` без скрытого усечения.

## 5. Регрессии и результаты

просмотра каталога, истории, контекста, прогресса и Save. Новый tool

# 015 — Удаление элементов секвенции

Статус: **пункты 1–6 выполнены; приёмка пройдена 2026-10-16**.
Полный локальный набор — 358 тестов; последний живой прогон — 37/37 сценариев
удаления и 12/12 регрессий. Браузерный Save проверен через локальный
postMessage-приёмник. Итоговые результаты и границы проверки — в разделе 11;
разделы 7–10 сохраняют историю промежуточных этапов.

Добавить инструмент `remove_sequence_elements`: по просьбе пользователя он
удаляет одно или несколько конкретных вхождений из выбранной секвенции
и создаёт один новый вариант. Например, удаление второй и четвёртой асан
превращает `[A, B, C, D, E]` в `[A, C, E]`.

Удаление использует полный активный снимок, историю вариантов, общий лимит
операций, прогресс и существующий Save. Подбор новых поз, поиск каталога
и TypeSafe для этой операции не требуются. В результате должен оставаться
хотя бы один элемент; исходный вариант сохраняется в истории.

Эта фича уточняет предварительный `remove_sequence_element` из раздела 9
спецификации 001: один tool принимает список вхождений. Удаление нескольких
вхождений, включая несоседние, считается одной операцией, а не несколькими
последовательными изменениями.

## 1. Запросы и разрешение ссылок

Поддерживаемые запросы:

- «Удали третью асану».
- «Убери первую и последнюю позы».
- «Удали вторую, четвёртую и пятую асаны».
- «Удали асаны со второй по четвёртую» — включительно.
- «Убери последние две асаны».
- «Удали Tree pose», если имя однозначно определяет вхождение.
- Выбор старого варианта через Previous/Next или Use this sequence, затем
  удаление именно из выбранного варианта.

Все ссылки разрешаются по актуальному `selected_sequence` до вызова tool.
Позиции начинаются с 1; «последняя» означает N. Перечень и диапазон относятся
к одному исходному снимку: после выбора второй асаны четвёртая не становится
пятой из-за промежуточного сдвига. Повторяющиеся ссылки на одно вхождение
ассистент сводит к одному UUID. Разные вхождения одного catalog item остаются
разными целями, даже если у них одинаковые названия и изображения.

Неоднозначное имя или местоимение, отсутствие цели («Удали асану») и просьба
сократить количество или длительность без указания удаляемых вхождений
требуют уточнения. Ассистент не выбирает лишние позы самостоятельно.
При любой позиции вне диапазона он объясняет проблему и не удаляет
остальные указанные элементы. При отсутствии полного выбранного снимка
объясняет, что для удаления нужна выбранная секвенция, без автогенерации.

«Что изменится, если удалить третью асану?» требует объяснения без изменения.
Однозначная просьба выполнить действие, включая «Можешь удалить третью?»,
не требует дополнительного подтверждения. Просьба удалить все элементы
или единственный оставшийся элемент получает объяснение ограничения;
ассистент не оставляет произвольно выбранную позу и не создаёт пустой вариант.

## 2. Контракт `remove_sequence_elements`

Аргументы, видимые модели:

| Аргумент | Тип | Назначение |
| --- | --- | --- |
| `sequence_uuid` | UUID-строка | UUID выбранного варианта |
| `element_ids` | Непустой список UUID-строк | Уникальные UUID удаляемых вхождений из актуального снимка |

`ToolRuntime` предоставляет состояние и `AssistantToolContext`; модель его
не передаёт. Отдельные `count`, `request`, позиции, catalog IDs, объекты
элементов и mirror flags инструменту не нужны. Полный текст текущего запроса
берётся из `context.user_request`.

Пустой список, `null`, неверные типы и невалидные UUID отклоняются стандартной
валидацией аргументов. Порядок UUID в списке не влияет на результат.
Повтор UUID в прямом вызове возвращает `invalid_arguments`, чтобы ошибка
вызывающего кода не приводила к неявному изменению числа удаляемых вхождений.

Порядок проверок после стандартной валидации:

1. При `require_generation=true` вернуть `generation_required`:
   Generate и Regenerate должны выполнять генерацию.
2. При `generation_started=true` или `turn_operation_committed=true` вернуть
   `operation_already_started`.
3. Прочитать полный снимок из `sequences[active_sequence_uuid]`;
   если его нет, вернуть `sequence_not_found`.
4. Сверить `sequence_uuid` с UUID активного снимка. Несовпадение возвращает
   `stale_sequence`, даже если переданный вариант есть в истории.
5. Проверить непустой исходный список; иначе вернуть `empty_sequence`.
6. Проверить непустой список целей и отсутствие повторов UUID;
   нарушение возвращает `invalid_arguments`.
7. Проверить наличие **всех** целей в исходном снимке. Любой неизвестный UUID
   возвращает `sequence_element_not_found`; частичного удаления нет.
8. Если удаляются все N вхождений, вернуть `would_empty_sequence`.
9. Создать и атомарно зафиксировать один новый вариант.

Ожидаемые ошибки используют существующий `tool_error`: `status=error`,
`code`, `message`, `ToolMessage.status=error` и правильный `tool_call_id`.
При ошибке новый UUID не создаётся, история и активный выбор не меняются,
`turn_operation_committed` не устанавливается. Исправленный вызов в этом же
запросе допустим; одинаковый неудачный вызов автоматически не повторяется.

У удаления нет успешного `no_change`: допустимый непустой набор всегда
удаляет хотя бы одно вхождение. Уже удалённый UUID в новом снимке возвращает
`sequence_element_not_found`, а не трактуется как успешно выполненная операция.

## 3. Семантика и новый вариант

Добавить `remove_elements` в `services/sequence_editor.py`. Сервис принимает
исходную `GeneratedSequence`, `element_ids` и текст запроса; независимо
проверяет непустой исходный список, непустой уникальный набор целей,
принадлежность всех UUID и непустой результат. Он возвращает новый
`GeneratedSequence`, а ожидаемые ошибки — через `SequenceEditorError`.
Состояние агента и commit остаются ответственностью tool.

Сервис удаляет целые `GeneratedSequenceElement` одним действием. Остальные
вхождения сохраняют относительный порядок, свои `element_id`, полный
`catalog_item`, `start_mirror` и `end_mirror`. Flags сохраняются точно,
включая значения, отличающиеся от `catalog_item.bilateral`. Зеркальная поза
считается одним вхождением и удаляется целиком. Удаление одного из повторов
catalog item не удаляет другие повторы. Итоговый `order` составляет `1..N-K`,
где K — число уникальных удаляемых вхождений.

| Поле нового варианта | Правило |
| --- | --- |
| `uuid` | Новый UUID |
| `family_uuid` | Сохраняется из выбранного варианта |
| `parent_uuid` | UUID выбранного варианта |
| `operation` | `remove` |
| `operation_request` | Полный текущий запрос пользователя |
| `generation_request` | Сохраняется исходный запрос генерации |
| `name`, `description`, `language` | Сохраняются |
| `elements_count` | Длина итогового списка |

Расширить допустимые значения `GeneratedSequence.operation` значением `remove`;
прежние `generate`, `regenerate`, `replace`, `swap` и `add` продолжают читаться.
Новый вариант создаётся глубокой копией без общих изменяемых объектов
с родителем. Исходный снимок и остальные варианты остаются неизменными.

Удаление первой, второй или последней позы не запускает повторный подбор,
проверку переходов или ограничений стартовой/второй/завершающей позы генератора.
Сохранившаяся первая поза не заменяется автоматически. Порядок и flags
оставшихся элементов определяются только исходным снимком.

Лимит генерации и добавления в 45 элементов не ограничивает удаление
из импортированных длинных снимков. Допустимо сократить 50 элементов до 49;
инструмент не удаляет дополнительные позы ради лимита. Число элементов
определяется фактическим списком, а не входным `elements_count`.
Существующие ограничения Save проверяются отдельно.

## 4. Commit, компактный результат и лимит операций

Расширить `tools/results.py:commit_sequence` полем `removal`. Успешный tool
возвращает один `Command`, который добавляет полный snapshot в `sequences`
через существующий merge-reducer, устанавливает `active_sequence_uuid`
и `turn_operation_committed=true` и добавляет компактный `ToolMessage`:

```json
{
  "status": "ok",
  "uuid": "<UUID нового варианта>",
  "operation": "remove",
  "elements_count": 3,
  "removal": {
    "removed_count": 2,
    "elements": [
      {"element_id": "<UUID B>", "name": "<имя B>", "old_order": 2},
      {"element_id": "<UUID D>", "name": "<имя D>", "old_order": 4}
    ]
  }
}
```

`removal.elements` перечисляет удалённые вхождения в порядке исходного списка,
независимо от порядка аргументов. Имена и `old_order` берутся из исходного
снимка; `removed_count` равен длине этого списка. Новый snapshot содержит
только оставшиеся вхождения; полные удалённые items доступны в родителе.
Полный snapshot, URLs, tags и catalog UUIDs в tool result не дублируются.
Этот контракт расширяет компактные результаты фичи 009.

Следующий вызов модели получает обновлённый `selected_sequence` и флаг commit.
Зарегистрировать tool в `ASSISTANT_TOOLS` и учесть в `SEQUENCE_TOOLS`
ограниченной истории. Проекции и суммаризация сохраняют смысл удаления
и не восстанавливают удалённые вхождения из старого tool result или summary.
Изменение schema и инструкций использует существующее обновление cache prefix;
отдельная маршрутизация запросов не вводится.

Один список удаляемых вхождений расходует **одну** успешную операцию за запрос.
Общий лимит охватывает генерацию, замену, обмен, добавление и удаление.
Повторная операция после удаления, в том числе с новым UUID, и удаление
после другой успешной операции возвращают `operation_already_started`.
Следующий пользовательский запрос сбрасывает лимит существующим механизмом.
Сохраняется правило одного tool call за один model message.

Системная инструкция должна отличать один набор удаляемых вхождений
от сочетания разных операций: «удали вторую и четвёртую» выполняется одним tool,
а «удали вторую и поменяй первую с третьей» требует уточнить одну операцию
до любых вызовов tools. Удаление нельзя имитировать заменой или Regenerate.

## 5. Прогресс, карточка и Save

В `response_progress_middleware.TOOL_STEPS` сопоставить инструмент коду
`updating_sequence` с заголовком `Removing sequence elements...`.
Успешный summary сообщает фактические K и итоговый размер, например
`Removed 2 sequence elements; 3 poses in total.` Ошибка завершает этап
с outcome `error`; текст успешной замены для удаления не используется.

Существующий `sequence_committed` публикуется ровно один раз после доступности
полного нового снимка в состоянии. События содержат правильные `request_id`,
`step_id`, `tool_call_id` и UUID результата. Предварительные `sequence_element`,
каталожная галерея, этапы поиска/TypeSafe и искусственный поэлементный прогресс
не создаются. Ошибка не создаёт commit и карточку секвенции.

Чат показывает новый вариант существующей карточкой с семейной историей,
Previous/Next, Use this sequence, Regenerate и Save. После обычного успешного
удаления итоговый текст ассистента пустой по актуальной политике ответа:
карточка уже показывает результат. Текст нужен для уточнения, ошибки
или отдельно запрошенного объяснения; он следует языку пользователя.

Save проецирует новый снимок: `info.uuid` — UUID нового варианта,
`info.elements_count` — N-K, миниатюры содержат только оставшиеся catalog UUIDs,
порядок и flags соответствуют результату. Повторный Save сохраняет UUID
варианта. Save родителя по-прежнему содержит полный исходный список.
Сохраняется существующая проверка импортного диапазона `1..75` без усечения.

Regenerate использует исходный `generation_request` и обычные правила
генерации; список удалённых вхождений не становится новым ограничением.
Rerun восстанавливает карточку без повторного удаления. Ошибка модели после
commit сохраняет новый вариант, активный выбор и возможность Save.

Новые кнопки удаления, очистка всей секвенции, физическое удаление вариантов
из истории или внешнего каталога, перемещение со сдвигом и отдельное изменение
зеркальности в эту фичу не входят.

## 7. Результаты пункта 1 — 2026-10-16

`GeneratedSequence.operation` принимает `remove`; прежние значения
`generate`, `regenerate`, `replace`, `swap` и `add` продолжают читаться.
В `services/sequence_editor.py` добавлен
`remove_elements(sequence, element_ids=..., request=...)`.

До создания UUID редактор проверяет непустой исходный список, непустой
уникальный набор целей, принадлежность всех UUID выбранному снимку и наличие
хотя бы одного оставшегося вхождения. Ошибки возвращаются через
`SequenceEditorError` с кодами `empty_sequence`, `invalid_arguments`,
`sequence_element_not_found` и `would_empty_sequence`. Частичного удаления нет.

Один вызов создаёт один новый вариант глубокой копией: family, исходный
generation request и метаданные сохраняются, parent указывает на выбранный
вариант, `operation=remove`, а operation request содержит полный переданный
текст без нормализации. Оставшиеся вхождения сохраняют UUID, полный catalog
item, относительный порядок и оба фактических mirror flags. Итоговый `order`
пересчитывается по списку, `elements_count` остаётся вычисляемым полем.
Исходник не меняется и не разделяет изменяемые объекты с результатом.

Удаление не применяет лимит генерации 45 или правила стартовой/второй/
завершающей позы, не подбирает новые позы и не требует доступных изображений
или catalog UUIDs. Проверен импортированный снимок из 50 элементов:
удаление одного даёт 49 без дополнительного усечения.

## 8. Результаты пункта 2 — 2026-10-16

В `tools/sequence.py` добавлен `remove_sequence_elements`, экспортированный
из `tools` и зарегистрированный в `ASSISTANT_TOOLS`. Модель передаёт только
`sequence_uuid` и непустой список UUID `element_ids`; runtime скрыт,
полный текст запроса берётся из `context.user_request`. Неверные типы,
невалидные UUID, пустой список и `null` отклоняет стандартная валидация.

Tool соблюдает порядок проверок: обязательная генерация, уже начатая
операция, наличие активного snapshot, его UUID, затем проверки редактора.
Ожидаемые ошибки возвращаются через `tool_error` с правильным `tool_call_id`
и `status=error`, без создания UUID или изменения состояния. Исправленный
вызов может выполниться в том же запросе. Каталог, generator factory
и TypeSafe для удаления не вызываются; `latest_catalog_items` сохраняется.

`commit_sequence` расширен необязательным `removal`: число удалённых
вхождений и только их UUID, имена и прежние позиции в порядке исходного
списка, независимо от порядка аргументов. Один `Command` передаёт полный
новый snapshot в merge-reducer, новый активный UUID, флаг commit
и компактный `ToolMessage`. Полные catalog items остаются в snapshots,
не дублируясь в результате tool.

В настоящем agent/tool loop со scripted model проверены сохранение родителя,

## 9. Результаты пункта 3 — 2026-10-16

В `services/assistant_agent.py:SYSTEM_PROMPT` удаление объявлено доступной
операцией через `remove_sequence_elements`. Один набор целей, включая
несоседний список или включительный диапазон, считается одной операцией.
Сочетание удаления с обменом, заменой, добавлением или генерацией требует
выбора одной операции до любых вызовов tools.

Все ссылки разрешаются по одному актуальному `selected_sequence` до удаления:
поддерживаются позиции, первая/последняя, последние K и однозначное имя.
Повторные ссылки на одно вхождение сводятся к одному UUID, в том числе
совпадающие имя и позиция; разные вхождения одной catalog item остаются
отдельными целями. Невалидная или неразрешённая ссылка отменяет весь набор,
без удаления корректной части. В инструкциях приведён контрольный пример
«удали вторую и шестую» для снимка из пяти поз.

Удаление всех поз или единственной позы получает объяснение ограничения
до вызова инструмента: должен оставаться хотя бы один элемент. Ассистент
не выбирает сохраняемую позу, не обрезает цели и не решает самостоятельно,
что удалить ради уменьшения количества или длительности. Удаление не требует
каталога и не имитируется заменой или Regenerate. Описание самого tool также
уточняет проверку полного набора до вызова.

Однозначное «Можешь удалить…?» выполняет действие без подтверждения;
гипотетический вопрос получает только объяснение. Обычный успешный результат
требует ровно ноль итогового текста. Уточнения, ошибки и отдельно запрошенное
объяснение остаются на языке текущего запроса, без объявления о завершении
и предложения продолжить. Версия cache prefix меняется существующим хешированием
промпта и описаний tools; новая маршрутизация не добавлена.

### Исправления по результатам живых проверок

Инструкции удаления приведены к явному порядку проверок: намерение выполнить
действие, наличие выбранного снимка, определённость целей, разрешение всего
набора, дедупликация, непустой результат и один вызов инструмента. N берётся
из фактического списка элементов, а не из исторического запроса генерации.
Добавлены короткие примеры для смешанных неверных ссылок, нулевой позиции,
повторяющегося имени, совпадающих имени и позиции, удаления единственной позы,
составных запросов и английского отказа удалить всё. Такой способ уточнения
инструкций соответствует рекомендации давать разнообразные примеры входов
и ожидаемых ответов в [OpenAI Prompt engineering](https://developers.openai.com/api/docs/guides/prompt-engineering#few-shot-learning).

В динамическом контексте `current_user_request` повторяет текущий запрос,
отделяя его от исторического `generation_request`. После успешного commit
модель не должна снова проверять уже выполненные ссылки по меньшему результату.
Язык примеров и метаданных не переопределяет язык текущего запроса.
Описания removal и swap уточняют неоднозначные ссылки; правило поиска кандидата
для replacement применяется только после проверки единственной операции.

отключённый reasoning и существующее обновление cache prefix. Новая маршрутизация,
парсер естественного языка и дополнительные вызовы модели для валидации не добавлены.

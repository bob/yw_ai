# 007 — Добавление элементов в секвенцию через TypeSafe

Статус: **реализовано; пункты 1–6 завершены. Автоматическая приёмка, живой
диалог и локальный браузерный Save пройдены**. Живой TypeSafe и запись во
внешний каталог в этой приёмке не выполнялись.

Добавить возможность подобрать от одного нового элемента до заполнения
выбранной секвенции до лимита **45 элементов**. Подбор выполняет тот же
`SequenceGenerator` с `TypeSafeService`, который используется для генерации.
Ассистент определяет количество, место вставки и пожелания пользователя,
а TypeSafe выбирает новые асаны из настоящего каталога.

Результат — один новый вариант выбранной секвенции. Существующие вхождения,
их относительный порядок, catalog items и mirror flags сохраняются.
Например, добавление двух элементов перед третьим превращает
`[A, B, C, D]` в `[A, B, X, Y, C, D]`. Весь блок подбирается и фиксируется
одной операцией; отдельные варианты для X и Y не создаются.

## 1. Сценарии и границы

Поддерживаемые запросы:

- «Добавь одну асану» — один элемент в конец.
- «Добавь ещё три асаны стоя» — три элемента в конец с указанным пожеланием.
- «Добавь две асаны перед третьей» или «после второй» — один блок внутри списка.
- «Добавь одну асану в начало» — перед первым вхождением.
- «Дополни секвенцию до 20 элементов» — добавить `20 - N` элементов.
- «Дополни до лимита» — добавить `45 - N` элементов.
- Выбрать старый вариант через Previous/Next или Use this sequence и дополнить
  именно его, даже если в истории есть более новый вариант.

Проектные решения: добавление доступно в любую позицию, по умолчанию — в конец;
при превышении свободного места добавляется доступное количество. Если место
не указано, дополнительное уточнение не требуется. Если количество не указано,
используется **1**, а не default генерации в 9 элементов.

Позиции исходного списка начинаются с 1. «Перед третьей» означает место 3,
«после третьей» — место 4, «после последней» — конец. Для явного места вставки
допустим диапазон `1..N+1`; `N+1` означает конец. Ссылка на несуществующую
асану, например «после шестой» при `N=5`, ошибочна.
Ассистент разрешает имена и местоимения по актуальному `selected_sequence`;
повторяющееся имя или неоднозначную ссылку уточняет до изменения.

В запросе «до 20» число означает итоговый размер, в запросе «ещё 20» — число
новых элементов. Если желаемый итоговый размер уже достигнут или меньше
текущего, ассистент объясняет это без вызова добавления и без удаления элементов.
Добавление по длительности не входит в эту фичу: если указана только
длительность дополнительного блока, ассистент уточняет количество.
Зеркальная асана считается одним элементом независимо от её длительности.

Вопрос о возможном добавлении или поиск кандидатов без просьбы применить их
не изменяет секвенцию. Однозначная просьба выполнить добавление, включая
«Можешь добавить…?», не требует дополнительного подтверждения.
Пожелания к новым асанам передаются в подбор; модель не составляет новый блок
сама и не применяет к нему механизм ручной замены.

Фича использует чат и существующую карточку результата. Новые кнопки,
drag-and-drop, удаление, перемещение существующих элементов, отдельное изменение
зеркальности и вставка нескольких блоков в разные места не входят в её объём.
Generate и Regenerate сохраняют назначение полной генерации.

## 2. Количество и лимит

Пусть `N = len(source.elements)`, `R` — запрошенное число новых элементов,
`available = max(0, MAX_SEQUENCE_ELEMENTS - N)`.
При `available > 0` инструмент вычисляет `K = min(R, available)`.
Подбор должен вернуть **ровно K** новых элементов; итоговый размер — `N + K`.

| Исходный размер | Запрос | Результат |
| --- | --- | --- |
| 9 | Добавить 1 | 10 элементов |
| 1 | Добавить 44 | 45 элементов |
| 9 | Довести до 45 | Добавить 36; итог 45 |
| 43 | Добавить 5 | Добавить 2; итог 45; объяснить ограничение |
| 45 | Добавить 1 | `no_change`, лимит достигнут |
| Больше 45 | Добавить 1 | `no_change`, свободного места нет; исходный вариант сохраняется |

Ограничение опирается на фактический список, а не на поле `elements_count`
из входного JSON. Используется существующая константа `MAX_SEQUENCE_ELEMENTS`;
отдельное значение 45 для добавления не заводится. Готовые импортированные
снимки могут иметь больший размер; добавление не сокращает их автоматически.
Правила чтения и Save таких снимков сохраняются.

Усечение допускается только из-за лимита размера и явно отражается в результате.
Недостаток пригодных кандидатов или ошибка TypeSafe не приводят к успешному
добавлению меньшего блока: операция завершается без commit.

## 3. Контракт `add_sequence_elements`

Аргументы, видимые модели:

| Аргумент | Тип | Назначение |
| --- | --- | --- |
| `sequence_uuid` | UUID-строка | UUID выбранного варианта |
| `count` | Строгое положительное целое | Запрошенное число **новых** элементов R |
| `request` | Непустая строка | Полный запрос на добавление с пожеланиями пользователя |
| `insert_before_element_id` | UUID-строка или `null`, default `null` | Вхождение, перед которым вставляется блок; `null` — конец |

`ToolRuntime` предоставляет состояние и `AssistantToolContext`, как в текущих
tools, и не является аргументом модели. Модель не передаёт catalog IDs,
готовые элементы, итоговое количество или mirror flags вместо аргументов.
Для «после второй» она передаёт UUID третьего вхождения; для вставки в начало —
UUID первого. UUID якоря берётся из выбранного снимка, а не из поиска каталога.

`count` сохраняет запрошенное количество, даже если оно больше 45:
например, `count=100` нормализуется инструментом до свободного места **до**
подбора. Верхняя граница относится к фактически добавленному блоку и итоговой
секвенции. Ноль, отрицательные значения, boolean, дроби и числовые строки
отклоняются стандартной строгой валидацией аргументов; пробельный `request`
возвращает `invalid_arguments`.

Порядок проверок после стандартной валидации аргументов:

1. При `require_generation=true` вернуть `generation_required`.
2. При `generation_started=true` или `turn_operation_committed=true` вернуть
   `operation_already_started`.
3. Прочитать полный активный снимок из `sequences[active_sequence_uuid]`;
   если его нет, вернуть `sequence_not_found`.
4. Сверить `sequence_uuid` с UUID активного снимка; несовпадение возвращает
   `stale_sequence`, даже если переданный вариант есть в истории.
5. Проверить непустой запрос и непустую исходную секвенцию. Для пустого списка
   вернуть `empty_sequence`: этот инструмент дополняет существующую секвенцию.
6. Если задан якорь, проверить его наличие; неизвестное вхождение возвращает
   `sequence_element_not_found`, включая снимок с уже достигнутым лимитом.
7. Вычислить доступное место. При `available=0` вернуть `status=no_change`,
   `code=sequence_limit_reached` и UUID исходного варианта.
8. Вычислить K, выполнить подбор, проверить весь блок и создать новый вариант.

Проверки 1–7 выполняются до создания генератора и обращений к каталогу/TypeSafe.
Ожидаемые ошибки используют существующий `tool_error` с `status=error`,
`code`, `message` и правильным `tool_call_id`. Ошибки и `no_change` не создают
вариант, не меняют активный UUID и не расходуют возможность успешного изменения
в этом запросе. После ошибки подбора ассистент объясняет проблему; одинаковый
неудачный вызов не повторяется автоматически.

## 4. Подбор и создание варианта

Добавить в `SequenceGenerator` метод `add_elements`, принимающий исходный
`GeneratedSequence`, запрос, `language`, фактическое количество K, необязательный
якорь и `progress_observer`. Он возвращает новые `CatalogItemSchema` в порядке
вставки и использует тот же каталог, конфигурацию TypeSafe и общий код подбора.
Его самостоятельный вызов проверяет `1 <= K <= 45 - N`, непустой исходный
список и якорь до сетевых обращений; некорректные значения не нормализуются молча.

Сервис не создаёт историю и не меняет исходный snapshot. Инструмент собирает
весь новый блок во временный список. `insert_elements` в
`services/sequence_editor.py` валидирует результат и собирает новый вариант.
Проверяются ровно K новых items, пригодность каждого для отображения и Save,
отсутствие повторов среди новых и существующих items и итоговый лимит.
Лишний, неполный или невалидный результат подставленного генератора возвращает
`invalid_addition_result` без сохранения. Итоговая проверка также применяет
жёсткие правила новых стартовых поз и изменённой первой/второй пары из
[selection.md](selection.md), чтобы подставленный генератор не обходил их.
Ожидаемая ошибка загрузки каталога возвращает `catalog_search_failed`,
а отсутствие пригодных кандидатов, невалидный ответ TypeSafe или сбой его
вызова — `addition_selection_failed`. Они не сохраняют частичный блок.
Неожиданная фатальная ошибка проходит через существующий путь завершения
запроса с ошибкой; до commit новый snapshot также не появляется.

Подробные правила выбора и контекста описаны в [selection.md](selection.md).
Добавление не вызывает `generate` для отдельной секвенции с новым случайным
стартом и не регенерирует существующие элементы.

| Поле нового варианта | Правило |
| --- | --- |
| `uuid` | Новый UUID |
| `family_uuid` | Сохраняется из выбранного варианта |
| `parent_uuid` | UUID выбранного варианта |
| `operation` | `add` |
| `operation_request` | Полный текущий запрос пользователя из runtime context |
| `generation_request` | Сохраняется исходный запрос генерации |
| `name`, `description`, `language` | Сохраняются |
| `elements_count` | Вычисляется из итогового списка |

Расширить `GeneratedSequence.operation` значением `add`; прежние снимки
`generate`, `regenerate`, `replace` и `swap` продолжают читаться.
Существующие вхождения сохраняют `element_id`, полный `catalog_item`,
`start_mirror` и `end_mirror`, включая flags, отличающиеся от `bilateral`.
Новые вхождения получают новые уникальные `element_id`, а оба mirror flags —
значение `catalog_item.bilateral`. Весь список получает `order=1..N+K`.
Исходный снимок и прочие варианты неизменны; новый вариант создаётся глубокой
копией без общих изменяемых объектов с родителем или кандидатами.

## 5. Commit и результат

Успешный инструмент возвращает один `Command`, который добавляет полный
snapshot в `sequences` через существующий merge-reducer, устанавливает
`active_sequence_uuid` и `turn_operation_committed=true` и добавляет `ToolMessage`
с `status=ok`, UUID, `operation=add`, `elements_count` и полем `addition`
по [контракту 009](../009-compact-gpt-tool-results/tool-contract.md).
Полный снимок остаётся в состоянии и следующем `selected_sequence`.
Содержимое `addition`:

```json
{
  "requested_count": 5,
  "added_count": 2,
  "limit_applied": true,
  "position": 3,
  "insert_before_element_id": "<uuid исходного третьего вхождения>",
  "elements": [
    {"element_id": "<uuid нового X>", "order": 3},
    {"element_id": "<uuid нового Y>", "order": 4}
  ]
}
```

`position` — начальная позиция блока, `elements` — новые вхождения в порядке
вставки; полные catalog items доступны в snapshot из `state.sequences`.
`limit_applied = requested_count > added_count`.
`no_change` при лимите содержит `uuid`, `code`, `message`, `requested_count`,
`added_count=0` и `limit_applied=true`, без нового снимка.
`latest_catalog_items` не читается и не обновляется внутренним подбором.

Один блок из K элементов считается **одной** операцией изменения.
Общий лимит одного успешного создания/изменения за запрос охватывает генерацию,
замену, обмен и добавление. Попытка второй операции, в том числе с UUID нового
варианта, отклоняется. Для нескольких мест вставки или сочетания добавления
с другой операцией ассистент уточняет, какую одну операцию выполнить первой.
Лимит сбрасывается в начале следующего пользовательского запроса.

После commit следующий вызов модели видит новый выбранный снимок. Ответ
на языке пользователя сообщает, сколько элементов добавлено, куда и сколько
стало всего. При усечении он называет лимит 45 и фактическое количество;
при `no_change` объясняет, что секвенция уже достигла лимита.

## 6. Прогресс, отображение и Save

Зарегистрировать tool в `ASSISTANT_TOOLS`, экспортировать его и обновить
системную инструкцию: добавление доступно через TypeSafe, единицей операции
является блок, default количества — 1, default места — конец.
Удалить добавление из списка недоступных операций; сохранить правила остальных.

В `TOOL_STEPS` использовать `updating_sequence` с заголовком
`Adding sequence elements...`. Внутренняя загрузка каталога публикует настоящий
подэтап `searching_catalog_items` через общий `GeneratorSearchProgress`.
Добавить сигнал прогресса добавления со счётчиками `completed=0..K`, `total=K`;
middleware преобразует его в существующий `step_progress`. Total — нормализованное
число новых элементов, а не R и не итоговый размер секвенции.

Добавление не публикует `sequence_element`: текущий контракт такого события
описывает предварительную генерацию с порядком от 1 и не кодирует вставку.
Во время подбора отображается прогресс; результат появляется целым после commit.
Внутренний подбор также не публикует `catalog_items_displayed` и отдельную
галерею. Для отдельно запрошенного показа кандидатов сохраняется обычный tool.

`sequence_committed` публикуется один раз после доступности полного снимка
в состоянии, через существующий `PendingSequenceCommit`/`confirm_commits`.
События имеют правильные request/step/tool IDs и UUID результата.
Успешный summary сообщает число добавленных элементов; ограничение размера
также отражается в summary. `no_change` завершает этап с соответствующим outcome,
ошибка — с `error`, оба без commit и новой карточки.

Карточка использует существующие Previous/Next, Use this sequence, Regenerate
и Save. Rerun восстанавливает результат без повторного вызова tools.
Ошибка финального ответа после commit сохраняет новый вариант и Save.
До commit исходный вариант остаётся выбранным и не заменяется частичным блоком.

Save передаёт новый `info.uuid`, реальную длину списка, catalog UUID каждого
item, актуальный порядок и flags. Повторный Save сохраняет UUID этого варианта.
Regenerate повторяет исходный `generation_request`; добавленный блок и
`operation_request` автоматически не переигрываются.

## 8. Результаты пункта 1 — 2026-10-12

В `SequenceGenerator` выделены общая загрузка каталога, фильтры кандидатов,
проверка второй позы и выбор пакета с предпочтением финиша. Добавлен
`add_elements(sequence, request, language=..., count=...,
insert_before_element_id=..., progress_observer=...)`: он проверяет аргументы
до сетевых обращений и возвращает весь подобранный блок списком, не меняя
исходный snapshot. Ошибка на любом шаге не возвращает частичный блок.
`count` здесь — уже вычисленное фактическое K; сервис не усекает его.

В `TypeSafeService` оба режима используют общий `Choice`, criteria из каталога,
проверку ответа и shortcut для единственного кандидата. Адаптер
`choose_addition_catalog_item` передаёт первоначальный и текущий запросы,
полные фиксированные prefix/suffix с исходными позициями и mirror flags,
уже выбранные добавления и счётчики текущего шага. Из state исключены image URLs
и rigman. Старт при prepend выбирается TypeSafe; жёсткие фильтры применяются
до пакета. Обычная генерация сохраняет случайный/явный старт и бюджет 40/80 секунд.
Observer пока сообщает загрузку каталога через `GeneratorSearchProgress`;
счётчики прогресса добавления и подключение к middleware относятся к пункту 4.

## 10. Результаты пункта 3 — 2026-10-12

Добавлен и экспортирован `add_sequence_elements`; инструмент зарегистрирован
в `ASSISTANT_TOOLS`. Модель видит только `sequence_uuid`, строгое положительное
целое `count`, непустой `request` и необязательный `insert_before_element_id`.
`ToolRuntime`, зависимости и язык каталога скрыты. Запрошенное количество
не ограничено сверху в схеме: инструмент вычисляет фактическое K по свободному
месту до вызова той же фабрики `SequenceGenerator`.

Проверки выполняются в порядке контракта: обязательная генерация, общий лимит
операций, полный активный snapshot, UUID выбранного варианта, запрос и непустой
список, якорь, свободное место. Длина берётся из `elements`, даже если входное
поле `elements_count` неверно. При достигнутом лимите возвращается `no_change`
с `sequence_limit_reached`, исходным UUID, счётчиками и `limit_applied=true`;
каталог и фабрика генератора не вызываются. Неизвестный якорь отклоняется
раньше проверки лимита, включая снимки с 45 и более элементами.

Подбор использует `add_elements`, а целый блок проходит `insert_elements`.
Ожидаемые ошибки каталога возвращают `catalog_search_failed`, ошибки TypeSafe —
`addition_selection_failed`, невалидный результат — `invalid_addition_result`.
Ошибка или `no_change` не расходует возможность успешного изменения в запросе.
Неожиданные ошибки передаются существующему пути завершения запроса с ошибкой.
Генерация отдельной секвенции и ручной выбор готового блока не используются.

Успех возвращает один `Command`: полный новый snapshot через merge-reducer,
новый `active_sequence_uuid`, `turn_operation_committed=true` и `ToolMessage`
с правильным `tool_call_id`. Поле `addition` содержит запрошенное и добавленное
количество, признак ограничения, позицию, якорь и IDs/orders новых вхождений.
`operation_request` берётся из полного пользовательского запроса runtime,
а запрос инструмента передаёт пожелания в подбор. Предыдущие варианты сохраняются;
внутренний подбор не читает и не изменяет `latest_catalog_items`.

## 11. Результаты пунктов 4–6 — 2026-10-12

Системная инструкция разрешает добавление через TypeSafe и задаёт default 1,
default конец, разницу «до N»/«ещё N», UUID якоря для before/after и prepend,

Вопрос о последствиях и поиск кандидатов не выполняют добавление; однозначное

Один блок входит в общий лимит операций вместе с генерацией, заменой и обменом.

`GeneratorAdditionProgress` сообщает выбор от 0 до фактического K.

карточка появляется целиком через существующий подтверждённый commit.

ошибка и `no_change` завершают этап без нового снимка. Некорректный или отсутствующий
ответ classifier преобразуется в ожидаемую ошибку выбора без частичного commit.

Существующая карточка и Save не потребовали нового UI. AppTest проверяет вставку,
catalog UUIDs, порядок и mirror flags, Previous/Next/Use this sequence, ветвление

достигнутый лимит и сохранение результата после ошибки финального текста.
Regenerate создаёт обычную регенерацию в той же family с parent результата

# 007 — Критерии приёмки добавления элементов

Статус: **пройдено 2026-10-12**: сервисы, tools, события и Streamlit AppTest,
28 сценариев живой LLM и локальный браузерный Save. Команды, результаты
и границы проверки зафиксированы в [README](README.md).
Каталог/classifier подставные; запись во внешний Asana Catalog не проверялась.

Связанные документы: [контракт фичи](README.md), [подбор через TypeSafe](selection.md).
Проверки сервисов и tools выполняются с fake catalog/classifier и scripted model;
они не требуют платных API. Живой диалог и браузерный Save дополняют их приёмкой
пользовательского поведения.

## 1. Состав и идентичность

1. Добавление одного и нескольких items в конец сохраняет все исходные
   элементы, создаёт ровно K новых вхождений и даёт непрерывный `order`.
2. Вставка в начало и перед внутренним вхождением создаёт один непрерывный блок:
   `[A, B, C, D] + [X, Y]` перед C даёт `[A, B, X, Y, C, D]`.
   Относительный порядок исходных элементов сохраняется.
3. Все прежние `element_id`, catalog fields и mirror flags сохраняются,
   включая flags, отличающиеся от `bilateral`. Новые IDs уникальны;
   у новых items оба flags равны `bilateral`.
4. Новый вариант имеет новый UUID, прежнюю family, parent выбранного варианта,
   `operation=add`, текущий `operation_request` и прежний `generation_request`.
   Метаданные сохранены. Изменение вложенного объекта нового варианта или
   кандидата после вызова не меняет родителя и остальные snapshots.
5. Элементы, уже повторяющиеся в исходном снимке, сохраняются. Новый кандидат
   с одинаковым ID или UUID любого исходного item, в том числе в хвосте,
   исключается; то же действует для ранее выбранных новых items.

## 2. Количество и валидация

6. Проверить `N=1, K=44`, `N=44, K=1` и заполнение `N=9` до 45.
   Итог содержит ровно 45 элементов; зеркальные items считаются по одному.
7. При `N=43, count=5` добавляются ровно 2; результат содержит
   `requested_count=5`, `added_count=2`, `limit_applied=true`.
   При `count=100` подбор также получает только свободное место.
8. При N=45 и N>45 результат — `no_change` с `sequence_limit_reached`;
   каталог, TypeSafe и фабрика генератора не вызываются, UUID/история неизменны.
   Следующая допустимая операция в этом запросе не блокируется из-за `no_change`.
9. Ноль, отрицательное количество, boolean, дробь и числовая строка отвергаются;
   пробельный request, пустой source, отсутствие снимка, устаревший UUID и
   неизвестный якорь также не вызывают подбор и не меняют состояние.
   Неизвестный якорь проверяется даже при достигнутом лимите.
10. Самостоятельный `SequenceGenerator.add_elements` отклоняет K больше
    свободного места, K=0, пустой исходный список и неверный якорь до каталога.
    Подставленный генератор с лишним/неполным блоком, невалидным catalog UUID,
    отсутствующей миниатюрой, повтором или нарушением жёстких правил первой/второй
    позы даёт `invalid_addition_result` без commit.

## 3. TypeSafe и правила выбора

11. Добавление использует тот же generator factory и общий `TypeSafeService`.
    Обычный `generate` не вызывается для создания отдельного блока;
    ассистент не передаёт самостоятельно выбранный список catalog IDs.
12. Fake classifier фиксирует state для каждого шага: полный prefix и suffix,
    исходный запрос, текущие пожелания, уже выбранные новые items,
    итоговый размер, правильную позицию и число оставшихся мест в блоке.
    Второй выбор видит первый. Image URLs и rigman отсутствуют.
13. При вставке перед C в `[A, B, C, D]` TypeSafe видит C/D и не считает
    последний новый item последним элементом секвенции. В конце списка
    финишная выборка выполняется только для последнего нового item.
14. Жёсткие фильтры до TypeSafe исключают повторы и новые `Other/Starting`
    вне позиции 1. Вставка в начало выбирает старт через TypeSafe;
    случайное распределение стартовой генерации не применяется к добавлению.
15. При добавлении в позицию 2 после лежащего старта допустимы только позы
    на спине; после стоячего старта исключены лежащие. Проверить одиночную
    вставку в начало с фиксированной второй позой и вставку нескольких
    элементов в начало. При отсутствии подходящих поз — ошибка без commit.
16. Вставка после второй позиции не отклоняется из-за уже изменённой старой
    первой/второй пары. Прежняя стартовая поза при prepend и прежняя финишная
    при append сохраняются. Предпочтения учитывают исходную скрутку и хвост.
17. Ошибка TypeSafe, отсутствующий ответ или неизвестный выбранный ID,
    пустой пул на первом или последующем шаге не сохраняют частичный блок.
    Результат содержит `addition_selection_failed`; ожидаемая ошибка загрузки
    каталога — `catalog_search_failed`.
    Единственный пригодный кандидат проходит те же фильтры без classifier call.

## 4. Агент, состояние и диалог

18. В реальном цикле агента со scripted model один tool call создаёт один
    `Command`, полный snapshot и структурированный `addition`; следующий вызов
    модели получает актуальную расширенную секвенцию. Старые снимки читаются.
19. Общий лимит отклоняет повторное добавление, замену/обмен после добавления
    и добавление после генерации/замены/обмена в одном запросе. Пакет из K поз
    расходует одну операцию. Следующий пользовательский запрос допускает новую.
    Generate/Regenerate отклоняют добавление с `generation_required`.
20. Сохраняется последовательное исполнение tools: несколько tool calls
    в одном model message отвергаются. Ошибка до commit допускает исправленный
    вызов; внутренний каталог добавления не читает/перезаписывает
    `latest_catalog_items` и не вызывает показ галереи.
21. На живой модели проверить русские и английские формулировки: одна/несколько
    асан, default 1, default конец, перед/после позиции, prepend, «до 20»,
    «ещё 20», «до лимита», ограничение свободным местом и достигнутый лимит.
    Просмотреть tool arguments и ответы: реальные UUID, правильная дельта,
    язык пользователя, фактическое количество и объяснение усечения.
22. На живой модели проверить старый выбранный вариант, повтор имени,
    неоднозначное местоимение, ссылку за диапазоном, отсутствие выбора,
    несколько мест вставки и добавление вместе с заменой/обменом.
    Уточнение не заявляет изменения. Вопрос о последствиях и поиск кандидатов
    не вызывают добавление; «Можешь добавить…?» выполняет однозначную команду.
    Только длительность приводит к уточнению количества.

## 5. Прогресс, карточка и Save

23. События содержат правильные request/step/tool IDs. Во время подбора
    видны этап добавления, реальный подэтап каталога и `completed=0..K`,
    `total=K`, включая count больше свободного места. Для вставки нет
    `sequence_element` и внутренней галереи.
24. Ровно один `sequence_committed` поступает после доступности полного нового
    snapshot в состоянии, затем этап завершается успешно. Ошибка и `no_change`
    имеют правильный outcome, summary и не создают commit/карточку.
25. Streamlit AppTest проверяет полный порядок, зеркальность, активный UUID,
    семейную историю и Previous/Next/Use this sequence, включая ветвление
    от старого выбранного варианта. Rerun не вызывает подбор повторно.
    Ошибка после нескольких выборов сохраняет исходный вариант;
    ошибка финального текста после commit сохраняет результат и Save.
26. Regenerate результата добавления передаёт исходный `generation_request`
    и создаёт обычную регенерацию в той же family с parent результата добавления;
    автоматически не повторяет добавленный блок.
27. В браузере проверить вставку внутри списка и повторный Save через
    существующий JavaScript-компонент: `info.uuid` нового варианта,
    `elements_count`, catalog UUIDs, порядок и flags совпадают со snapshot.
    Два Save одного варианта передают одинаковый UUID и payload;
    Save предыдущего варианта передаёт его исходный состав.

## 6. Регрессии и фиксация результатов

Пройти существующие проверки генерации, начальной/второй позы, длительности,
лимита 45, замены, обмена, каталога, истории и прогресса. Обычная генерация
сохраняет своё потоковое отображение и прежние интерфейсы сервисов.

В конце реализации записать в README фичи команды, фактические результаты
автоматических проверок, живого диалога и браузерного Save. Отдельно указать,
проверялся ли только browser handoff или также сохранение во внешнем каталоге.
Сам факт наличия критериев не считается пройденной приёмкой.

# Спецификация: общий агент приложения

Статус: **первый этап реализован**; общий агент, контекст секвенции и замена
одного элемента за запрос с сохранением истории выполнены.
Типизированный stream-контракт остаётся последующим расширением.
Границы текущего этапа описаны в [плане](README.md).
Связанные документы: [catalog tools](catalog-tools.md),
[состояние и редактирование секвенции](sequence-context.md).

## 1. Проблема и ожидаемое поведение

До реализации этого этапа `services/sequence_agent.py` создавал агента внутри каждого вызова
`generate()`. Агент получает только текущий запрос, обязан вызвать
`generate_sequence` ровно один раз и завершает работу после tool с
`return_direct=True`. Генерация передаёт элементы в UI через custom stream,
но возвращает модели только текст о том, что результат показан пользователю.

Новый агент обслуживает диалог: генерирует секвенции, ищет элементы, получает
теги, отвечает на вопросы о текущей секвенции и заменяет её элементы.
Один запрос может потребовать нескольких последовательных tools, например
получение тегов → поиск → замена. Уточняющий вопрос или ответ на основании
уже имеющегося контекста может обойтись без tools.

## 2. Разделение ответственности

Предлагаемая структура относительно `src/langchain_app/`:

| Модуль | Ответственность |
| --- | --- |
| `services/assistant_agent.py` | `AssistantAgent`, сборка `create_agent`, запуск диалога, нормализация stream-событий |
| `services/sequence_generator.py` | Существующий алгоритм генерации и выбор через TypeSafe |
| `services/catalog_item.py` | HTTP-поиск catalog items без зависимости от LangChain и Streamlit |
| `services/catalog_tag.py` | HTTP-получение catalog tag names |
| `services/sequence_editor.py` | Проверяемые операции над секвенцией, начиная с замены |
| `tools/sequence.py` | Tools генерации и замены, связывающие сервисы с состоянием агента |
| `tools/catalog.py` | Tools поиска и получения тегов |
| `schemas/assistant.py` | Состояние агента, команды приложения и события |
| `schemas/catalog.py` | Catalog DTO и аргументы поиска; общие типы не привязаны к секвенции |
| `schemas/generated_sequence.py` | Полная сгенерированная секвенция и её элементы |
| `dependencies.py` | Создание клиентов, сервисов, tools и агента |
| `ui/sequence.py` и entrypoint | Отображение событий и выбор варианта |

Названия новых модулей — предложение для ревью. Клиенты работают с API,
сервисы — с предметными данными, tools — с состоянием и tool messages,
агент — с моделью и набором tools, UI — с отображением.
Предметные схемы не импортируют типы из `ui/`.

Оставляем один LangChain-агент через `create_agent`; отдельные агенты и
самописный граф для этих сценариев не требуются. Добавление следующего tool
не должно требовать изменения алгоритма генерации или stream-контракта UI.

## 3. Tools и правила маршрутизации

| Tool | Когда используется | Изменяет секвенцию |
| --- | --- | --- |
| `generate_sequence(request, count)` | Пользователь просит новую секвенцию или Regenerate | Создаёт вариант |
| `search_catalog_items(...)` | Нужны реальные элементы каталога или кандидаты для замены | Нет |
| `get_catalog_tag_names()` | Нужны доступные теги или корректный фильтр по тегам | Нет |
| `replace_sequence_element(...)` | Пользователь просит применить замену в выбранной секвенции | Создаёт вариант |

Tools объявляются отдельно от метода запуска агента. Сервисы и runtime
передаются приложением, а не выбираются моделью. Ни base URL, ни UUID папки,
ни язык API не входят в аргументы, видимые модели.

Правила system prompt:

- Для новой секвенции вызывать генерацию и передавать полный смысл запроса,
  включая ограничения. Не составлять секвенцию из выдуманных элементов.
- Для поиска использовать catalog tool; не подменять результат знаниями модели.
- Для неизвестных тегов сначала получить реальные имена tags из API.
- Вопрос о составе уже выбранной секвенции можно обработать по её снимку.
- Для замены использовать проверяемую операцию; текстовый ответ сам по себе
  не изменяет секвенцию.
- При неоднозначном указании элемента, варианта или конкретной замены задать
  уточняющий вопрос. Поиск альтернатив не означает разрешение применить замену.
- В одном запросе заменять не более одного элемента; при просьбе о нескольких
  заменах сначала уточнить, какой один элемент изменить.
- Добавление, удаление, перемещение и самостоятельное изменение зеркальности
  пока недоступны. Объяснять ограничение без подмены этих операций генерацией
  или заменой. Их точный состав как последующего расширения можно изменить на ревью.
- Отвечать на языке пользователя; имена и теги каталога оставлять в форме API.

Убираются глобальное требование «генерация ровно один раз на каждый запрос»
и ошибка для любого текстового ответа без tools. Для команды кнопки Generate
или Regenerate успешное завершение требует нового варианта; текст вместо
результата такой команды не считается успешной генерацией.

## 4. Контракт генерации

`generate_sequence` сохраняет текущие аргументы: непустой `request` и целый
`1 <= count <= 45`. Язык данных — `en`, задаётся приложением.

Правила определения количества сохраняются:

1. Явное число элементов имеет приоритет над длительностью.
2. При одной длительности: `minutes × 60 / 40`, округление половины вверх,
   минимум один элемент. Это верхняя оценка: обычная асана занимает 40 секунд,
   билатеральная — 80 секунд, оставаясь одним элементом. Модель передаёт
   `duration_seconds`, а генератор учитывает фактически выбранные асаны.
   Например, 10 минут → до 15 элементов, меньше при зеркальных асанах.
3. Если число и длительность отсутствуют — 9 элементов.

Обязательный предел любой генерации — 45 элементов; большие запросы
ограничиваются этим числом. Актуальные правила длительности и проверки лимита
описаны в [спецификации 005](../005-sequence-duration-and-limit/README.md).

До работы генератора валидируются аргументы. Существующий генератор сохраняет
стартовый элемент с `Other/Starting`, выбор последующих через TypeSafe,
отсутствие повторов и предпочтение `Other/Finishing` в конце.
Выборка для генератора описана отдельно в [catalog tools](catalog-tools.md).

Tool собирает полные `CatalogItemSchema`, одновременно отправляя события
прогресса. После успешного завершения подбора по количеству или времени он возвращает
обновление состояния с полным снимком секвенции и компактный `ToolMessage`
с `status`, UUID, `operation` и `elements_count` по [контракту 009](../009-compact-gpt-tool-results/tool-contract.md).
Генерация не использует `return_direct=True`: модель получает результат и
может завершить ответ или продолжить разрешённую цепочку чтения данных.

## 5. Диалог, команды и события

Публичный интерфейс сервиса заменяет `generate() -> Iterator[CatalogItemSchema]`
на `stream(request: AssistantRequest) -> Iterator[AssistantEvent]`.

`AssistantRequest` содержит текст, `request_id` и intent
`chat | generate | regenerate`; для Regenerate — UUID исходного варианта.
`thread_id` и зависимости передаются приложением в конфигурации запуска.
Смена выбранного варианта — отдельная операция приложения без вызова модели.

События — типизированные объекты с полем `type`, `request_id` и payload:

| Событие | Payload и назначение |
| --- | --- |
| `text_delta` | Фрагмент видимого ответа ассистента |
| `sequence_started` | Идентификатор операции; подготовка области прогресса |
| `sequence_element` | Идентификатор операции, позиция и полный элемент; предварительное отображение |
| `sequence_committed` | Полная сохранённая в состоянии версия, её UUID и родитель; окончательное отображение |
| `catalog_items_found` | Фильтры и полученные items; самостоятельный результат поиска |
| `catalog_tags_found` | Список tag names; самостоятельный результат получения тегов |
| `error` | Код, понятное сообщение и идентификатор операции, если есть |

Событие `sequence_committed` создаётся после применения обновления состояния,
а не при отправке последней миниатюры. Оно одинаково для генерации и замены.
Пустой поиск — `catalog_items_found` с пустым списком, а не ошибка.
UI сохраняет и текстовые ответы, и уточняющие вопросы без секвенции.
Tool messages и аргументы tools не выводятся как текст ассистента.

## 6. Жизненный цикл и ошибки

Агент использует состояние и checkpointer диалога из
[спецификации контекста](sequence-context.md). Создание сервиса на rerun не
должно терять историю; наличие checkpointer важнее срока жизни экземпляра.
Streamlit-клиенты и сервисы инициализируются на script thread до выполнения
tools. Tools не вызывают `st.*`.

В первом этапе tools выполняются последовательно; у модели сохраняется
`parallel_tool_calls=False`, а обработчик отклоняет параллельные изменения
состояния. За один запрос допускается одно создание/изменение секвенции.
Для цепочки чтения и замены предлагается `recursion_limit=20` вместо текущих 6.
Предел означает остановку с понятной ошибкой, без автоматического повтора
генерации или изменения.

Ошибки аргументов и ожидаемые ошибки catalog/editor возвращаются как
`ToolMessage` с `status=error`, кодом и сообщением; модель может исправить
аргументы или объяснить отсутствие результата. Ошибки провайдера модели и
превышение лимита оборачиваются в `AssistantAgentError` и событие `error`.
Программистские ошибки не маскируются успешными ответами.

Если генерация прервалась, её предварительные элементы не становятся вариантом.
Если изменение уже применено, а последующий текстовый ответ модели не удался,
вариант остаётся сохранённым: UI показывает результат операции и отдельно
ошибку ответа. Rerun сверяет UI с состоянием, чтобы не потерять применённый вариант.

## 7. Миграция и критерии приёмки

Переименовать `SequenceAgent`/`SequenceAgentError`, factory, импорты и тесты.
Предлагаемая настройка модели — `ASSISTANT_AGENT_MODEL`; временный порядок:
непустой `ASSISTANT_AGENT_MODEL` → непустой `SEQUENCE_AGENT_MODEL` → текущий
default `openai:gpt-6-luna`. Миграция описана в [014](../014-gpt-6-luna/README.md).
Entrypoint переименован в `assistant.py`, поскольку приложение обслуживает
не только генерацию секвенций. Команда запуска и путь в UI-тестах обновлены.

Приёмка с fake model и fake services, без платных API-вызовов:

- Генерация начинает отображать элементы до окончания работы генератора.
- Правила count, исходный запрос и существующий алгоритм выбора сохранены.
- Запрос поиска не запускает генератор; запрос тегов вызывает tags tool.
- Цепочка tags → search → replace выполняется в одном диалоге.
- Текстовый ответ и уточнение сохраняются в истории без ошибки «tool не вызван».
- Generate/Regenerate не объявляются успешными без `sequence_committed`.
- Неуспешная генерация сохраняет предыдущий вариант; ошибка текста после
  успешной операции не отменяет новый вариант.
- Подключение ещё одного tool не требует изменений `SequenceGenerator`.

## 8. Проверенные механизмы LangChain

Расширяемое состояние и память диалога доступны через `AgentState` и
checkpointer. [LangChain: short-term memory](https://docs.langchain.com/oss/python/langchain/short-term-memory).
Tools читают runtime state и возвращают обновления через `Command` вместе с
`ToolMessage`. [LangChain: tools](https://docs.langchain.com/oss/python/langchain/tools#update-state).

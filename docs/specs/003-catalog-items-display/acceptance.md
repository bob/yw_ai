# Приёмка фичи 003: Отображение элементов каталога

Основной документ: [план фичи](README.md).

Автоматические проверки выполнять с тестовой моделью и mock каталога,
без платных API-вызовов, по существующим примерам тестов агента и Streamlit.

## Пользовательское намерение

1. **«Покажи асаны сидя в наклоне».** После поиска агент вызывает
   `show_catalog_items` для подходящих элементов. Отображаются их тамбы
   без создания секвенции.
2. **«Какие есть позы лежа».** Вопрос о доступных элементах тоже приводит
   к показу. Для маршрутизации не требуется буквальное слово «покажи».
3. **«Покажи ещё варианты».** Продолжение каталожного запроса создаёт
   подборку в новом ответе. Старое сообщение сохраняет прежние тамбы.
4. **«Найди кандидатов для замены, пока ничего не меняй».** Агент ищет
   подходящие варианты и вызывает `show_catalog_items`. Кандидаты видны
   тамбами. `replace_sequence_element` и генератор не вызываются;
   выбранный UUID, элементы секвенции и история вариантов остаются прежними.
   Запрет изменения не препятствует показу и не требует подтверждения.
5. **Обычный вопрос.** «Как выполнять наклон сидя?» и запрос тегов
   не приводят к вызову показа или появлению галереи.

## Tool, события и история

6. **Выбор после нескольких поисков.** Поиски возвращают разные наборы,
   и галерея не появляется. Затем `show_catalog_items` получает выбранные ID
   из последней проверенной выборки. Отображается только этот список
   в порядке аргументов, а не вся выдача поиска.
7. **Проверка данных.** Неизвестные ID, повторные ID и пустой список
   отклоняются без события показа. Tool получает изображения и имена
   из проверенных данных каталога, не из аргументов модели.
   Показ не изменяет `latest_catalog_items` и состояние секвенций.
8. **Пустой или неуспешный поиск.** Галереи нет. Существующие исходы этапов
   и очистка кандидатов для замены сохраняются. Попытка показать прежние
   кандидаты после их очистки отклоняется.
9. **Ошибка модели до показа.** Поиск успешен, но модель падает до
   `show_catalog_items`. Тамбы не появляются и не записываются в историю.
10. **Ошибка текста после показа.** Показ успешен, следующий model call
    падает. Подборка сохраняется в сообщении и после rerun рядом с ошибкой.
11. **Связь событий.** Успешное действие показа даёт одно
    `catalog_items_displayed` внутри своего этапа и с проверенными данными.
    JSON round-trip сохраняет данные. Ни один поиск не даёт такого события.
    За запрос допускается один успешный показ; повторный вызов не дублирует
    и не заменяет подборку.
12. **Изоляция и rerun.** Чужие и повторные события, а также события после
    завершения запроса не меняют UI. Галерея воспроизводится из `ChatMessage`
    без обращений к модели или каталогу. Более поздний поиск не меняет
    уже сохранённую подборку.
13. **Совместимость.** Старые сообщения без `catalog_items` отображаются
    без ошибок. Адаптеры `stream` и `generate` сохраняют прежние типы выдачи.
    Отсутствие итогового текста не скрывает успешное действие показа.

## Внешний вид и существующие операции

14. **Только тамбы.** Каталожная область расположена вне блока прогресса,
    после текста. В ней нет кнопок, метаданных секвенции, ID элементов,
    счётчика поз, подписи активного варианта и mirror-скобок,
    в том числе у `bilateral=true`.
15. **Общие стили.** Сравнить тамб каталога и тамб секвенции с одним URL:
    размер, скругление, обрезка, интервалы и перенос одинаковые.
    Изменение общего размера применяется к обоим; CSS не продублирован.
16. **Нет изображения.** При `image_url=null` на месте элемента отображается
    fallback с реальным именем. Остальные тамбы доступны. Спецсимволы
    в имени и URL корректно экранируются.
17. **Генерация и Regenerate без изменений.** Generate, Regenerate и
    «Сгенерируй секвенцию из 12 поз» используют прежний поток.
    Внутренние поиски и возможные самостоятельные поиски агента не вызывают
    `show_catalog_items` и не создают каталожную галерею. Прогресс,
    потоковые тамбы секвенции, mirror-скобки, варианты и Save сохраняются.
18. **Замена без изменений.** «Замени вторую позу на позу сидя в наклоне»
    выполняет существующий поиск и замену, без отдельной галереи каталога.
    Проверка кандидатов, новый UUID, история вариантов, кнопки и Save
    работают как раньше.
19. **Совместный явный запрос.** Если пользователь отдельно просит показать
    элементы и выполнить операцию над секвенцией, показанные элементы
    и секвенция размещаются раздельно. Сам показ не выбирает вариант,
    не создаёт секвенцию и не считается её изменением.

## Проверка реализации

Дополнить существующие проверки событий, tools и Streamlit-проходов.
При проверке маршрутизации включить запросы на показ, вопрос о доступных
позах, подбор кандидатов без изменения и обычные запросы генерации и замены.
Отдельно проверять отсутствие события показа при служебном поиске без
`show_catalog_items` и отсутствие замены при просьбе только найти кандидатов.

Визуальную приёмку общих стилей выполнить в браузере на тестовых данных,
включая узкую ширину контейнера и длинную подборку в пределах текущего
лимита поиска.

После реализации запустить существующий комплект:

```bash
uv run python -m unittest discover -s tests -v
```

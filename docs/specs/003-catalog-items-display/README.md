# Фича 003: Отображение элементов каталога

Статус: **план; реализация не начата**. Создано: 2026-10-09. Обновлено: 2026-10-10.
Проверки: [приёмочные сценарии](acceptance.md).

Связанные документы: [инструменты каталога](../001-create-assistant-agent/catalog-tools.md),
[контекст секвенции](../001-create-assistant-agent/sequence-context.md),
[прогресс ответа](../002-assistant-response-progress/README.md).

## 1. Проблема и цель

Когда пользователь просит найти или показать элементы каталога для просмотра,
ассистент сейчас отвечает названиями и ID. Нужно показывать их миниатюрами,
аналогично элементам секвенции, в отдельной области ответа.

**Показ каталога выполняется только по пользовательскому запросу на просмотр
или подбор доступных элементов, включая кандидатов для замены.
Сам вызов поиска тамбы не отображает.**
Например, «Покажи асаны сидя в наклоне», «Какие есть позы лежа» и
«Найди кандидатов для замены, пока ничего не меняй» должны давать подборку
тамбов. Генерация секвенции и замена элемента сохраняют
существующее поведение, включая поиски, прогресс, карточки и кнопки.

В каталожной области — только тамбы, без кнопок и параметров секвенции.
Размер, скругление, обрезка изображения, интервалы и перенос строк берутся
из того же общего рендерера и стилей, что использует секвенция.

## 2. Текущее устройство

- [search_catalog_items](../../../src/langchain_app/tools/catalog.py) возвращает
  модели проверенные данные API, включая ID, UUID, имя, URL изображения,
  bilateral и теги. Данные записываются в `latest_catalog_items`
  для проверки последующей замены элемента секвенции.
- [CatalogItemService](../../../src/langchain_app/services/catalog_item.py)
  уже получает `image_url`; изменение endpoint или дополнительная загрузка
  карточек по ID для этой фичи не требуются.
- [AssistantAgent](../../../src/langchain_app/services/assistant_agent.py)
  передаёт UI типизированные события прогресса, текст и элементы секвенции.
  Отдельного действия показа каталога пока нет.
- [SequenceRenderer](../../../src/langchain_app/ui/sequence.py) содержит CSS,
  HTML миниатюры и контейнер с переносом строк. Сейчас размер по умолчанию —
  64 × 64 px, `object-fit: cover`, скругление 10 px, интервал `xxsmall`.
- [ChatMessage](../../../src/langchain_app/schemas/chat.py) сохраняет текст,
  выполнение и варианты секвенции, но не самостоятельную подборку каталога.

## 3. Когда показывать каталог

Маршрутизацию определяет основной агент по смыслу пользовательского запроса.
Не требовать буквального слова «покажи»: вопрос о доступных позах каталога
или просьба подобрать кандидатов для просмотра тоже является запросом
на их показ. Фраза «пока ничего не меняй» запрещает изменение секвенции,
но позволяет показать найденных кандидатов. Простое наличие служебного
поиска в выполнении не разрешает отображение.

| Пользовательский запрос | Ожидаемое поведение |
| --- | --- |
| «Покажи асаны сидя в наклоне» | Найти подходящие элементы и показать их тамбы |
| «Какие есть позы лежа» | Найти подходящие элементы и показать их тамбы |
| «Покажи ещё варианты» после каталожной подборки | Найти и показать новую подборку в новом ответе |
| «Сгенерируй секвенцию из 12 поз» | Существующая генерация, без отдельной галереи каталога |
| «Замени вторую позу на позу сидя в наклоне» | Существующий поиск и замена, без отдельной галереи каталога |
| «Найди кандидатов для замены, пока ничего не меняй» | Найти кандидатов и показать их тамбы; секвенцию не менять |
| «Как выполнять наклон сидя?» | Обычный ответ; вопрос о технике не включает показ каталога |

Уточнить system prompt и описание нового tool: показ используется для
пользовательского просмотра каталога и подбора вариантов, включая кандидатов
для будущей замены. Служебные поиски внутри выполнения генерации, замены
или подготовки обычного ответа не вызывают показ. Просьба найти кандидатов
без изменения секвенции вызывает показ и не разрешает замену.
Отдельный LLM-классификатор намерения и дополнительное подтверждение
пользователя не нужны.

## 4. Разделение поиска и показа

Добавить отдельный tool `show_catalog_items(catalog_item_ids)`.
Обычный сценарий просмотра:

1. Агент получает запрос на просмотр доступных элементов или подбор кандидатов.
2. При необходимости получает теги и выполняет один или несколько
   `search_catalog_items`. Эти вызовы дают только существующий прогресс
   и данные модели; галерея ещё не появляется.
3. Агент выбирает подходящие запросу элементы из проверенной выборки
   и передаёт их ID в `show_catalog_items`.
4. UI получает событие показа и отображает выбранные тамбы.
   Ассистент может добавить краткое пояснение на языке пользователя.

Аргументы показа содержат непустой список ID, без имён, URL, mirror flags
или данных секвенции. Tool разрешает ID по `latest_catalog_items`,
валидирует данные как `CatalogItemSchema` и передаёт отделённый снимок.
Порядок аргументов определяет порядок показа. Неизвестные и повторные ID
отклоняются; выдуманные URL и элементы недопустимы.

При нескольких поисках агент выбирает из последней проверенной выборки,
как допускает существующее состояние каталога. Не показывать автоматически
все результаты, не собирать галерею из истории поисков и не разбирать
названия или ID из свободного текста модели.

За один пользовательский запрос достаточно одного успешного действия
показа с полной выбранной подборкой. Признак выполненного показа ограничен
контекстом запроса и не использует `turn_operation_committed`.
Новый tool не изменяет `latest_catalog_items`, выбранный вариант или секвенции.
Generate/Regenerate не используют этот tool; он отклоняет вызов в контексте
обязательной генерации или Regenerate.

Существующие `search_catalog_items`, `generate_sequence`,
`replace_sequence_element`, проверка кандидатов и алгоритм генератора
сохраняют контракты и поведение. Поиск и замена не получают параметр
автоматического отображения.

## 5. Поведение интерфейса и ошибки

Подборка размещается в сообщении ассистента после текста, вне блока выполнения.
Её место резервируется заранее; тамбы появляются после успешного
`show_catalog_items`, без искусственной задержки. Итоговый текст модели
может появиться позже. Если пользователь отдельно запросил показ каталога
и операцию над секвенцией, их области отображаются раздельно.

В каталожной области:

- только изображения, без Save, Regenerate, Use this sequence и Previous/Next;
- нет имени, описания, ID, языка и количества поз секвенции;
- нет постоянных подписей с ID, тегами или параметрами элементов;
  реальное имя используется как доступный `alt`;
- нет mirror-скобок, в том числе у `bilateral=true`: параметры вхождения
  в секвенцию здесь отсутствуют;
- при `image_url=null` сохраняется место элемента с текстовым fallback-именем,
  как в существующем рендерере. Не генерировать заменяющее изображение.

Пустой поиск или ошибка поиска не создают галерею. Ассистент сообщает
об отсутствии результатов или ошибке по существующим правилам прогресса.
Если показ ещё не был выполнен и последующий ответ модели упал, тамбов нет:
успешного поиска самого по себе недостаточно.

Ошибка валидации `show_catalog_items` не публикует событие показа.
Если показ выполнен, а подготовка итогового текста упала, подтверждённые
тамбы сохраняются в сообщении рядом с ошибкой. Последующие поиски сами
по себе не очищают и не обновляют уже показанную подборку.
Другие сообщения чата всегда сохраняют свои снимки.

## 6. Событие и хранение

Добавить `CatalogItemsDisplayedEvent` с `type="catalog_items_displayed"`
в существующий `ResponseEvent`.

| Поле | Назначение |
| --- | --- |
| `request_id`, `event_index`, `elapsed_seconds` | Принадлежность запросу, порядок и время |
| `step_id`, `tool_call_id` | Связь с конкретным вызовом `show_catalog_items` |
| `items` | Непустой список проверенных `CatalogItemSchema` в выбранном порядке |

Событие публикуется только после полной успешной проверки аргументов показа,
до завершения соответствующего этапа. Данные поступают из нового tool;
middleware оформляет их как событие с идентификаторами этапа.
Никакой поиск, включая самостоятельный `search_catalog_items`
и внутренний поиск генератора, это событие не публикует.

В прогресс добавить этап нового tool, например `Showing catalog items...`,
с кратким результатом о числе показанных элементов. Существующие этапы
поиска, генерации и замены остаются прежними. Событие показа не является
`sequence_element` или `sequence_committed`.

В `ChatMessage` добавить необязательное поле `catalog_items` со снимком
именно показанных элементов. Без события показа это поле отсутствует
или пустое. Сохранять снимок вместе с текстом и `execution`,
включая ошибку последующего обращения к модели.

Rerun воспроизводит подборку из сообщения без обращения к агенту,
каталогу или модели. Изменение `latest_catalog_items` не меняет историю.
Хранение ограничено текущей Streamlit-сессией. Снимок UI отдельно в prompt
не добавляется. Старые сообщения без нового поля остаются совместимыми.
Существующую ветку Regenerate в `assistant.py` менять для показа не требуется.

## 7. Общий рендерер миниатюр

Вынести из `SequenceRenderer` в общий модуль `ui/thumbnails.py`:

- CSS миниатюр и настройку размера;
- безопасную HTML-разметку изображения и существующих mirror-скобок;
- горизонтальный контейнер с переносом строк и fallback.

`SequenceRenderer` и новый `CatalogItemsRenderer` используют этот модуль.
Стили подключаются один раз на странице. Размер и визуальные параметры
сохраняются; изменения общих стилей применяются к обоим окружениям.
Не копировать CSS и не создавать фиктивный `SequenceView` для каталога.

Проекция секвенции передаёт её реальные mirror flags, проекция каталога —
URL и имя без скобок. Имя и URL экранируются общим рендерером.
Текущие импорты UI и типы миниатюр остаются совместимыми.
Извлечение общего кода сохраняет внешний вид и поведение секвенции.

## 9. Границы фичи

Фича включает показ по пользовательскому запросу, общие стили и сохранение
подборок в истории. Клики по тамбам, добавление в секвенцию, новые фильтры,
пагинация, подробная карточка и постоянное хранение требуют последующих фич.

Генерация секвенции, Regenerate, замена элемента, история вариантов и Save
сохраняют существующее поведение. Новые зависимости и изменение API каталога
не планируются. Приёмка проверяет отсутствие автоматического показа после
поиска и регрессий секвенции при выделении общего рендерера.

# 008 — Сообщение об исчерпании API-кредитов

## Задача

При проверке 2026-10-12 OpenAI API вернул HTTP 429, `type=insufficient_quota`
и `code=credit_balance_exhausted`. Интерфейс показывал только
`Could not complete request. Please try again.`, поэтому причина отказа
и необходимое действие были скрыты.

## Поведение

Обработка использует структурированные `code` и `type` из исключения OpenAI SDK,
включая подкласс LangChain `OpenAIRateLimitError` и исходную причину обёртки.
Классификатор явно проверяет HTTP 429; другие HTTP-статусы сохраняют общее сообщение.
Текст ответа модели или текст исключения для распознавания не используется.

| Ответ API | Публичное сообщение |
| --- | --- |
| HTTP 429, `code=credit_balance_exhausted` | `OpenAI API credits have run out. Add credits in OpenAI billing settings to continue.` |
| HTTP 429, `code=insufficient_quota`, либо отсутствует code и `type=insufficient_quota` | `OpenAI API quota has been exceeded. Check your credits and usage limits in OpenAI billing settings before trying again.` |
| Другие коды, включая временный rate limit и конкретные spend/usage limits | Прежнее общее сообщение |

`OpenAI billing settings` — ссылка на
<https://platform.openai.com/settings/organization/billing/>.
Сообщения на английском соответствуют существующему языку интерфейса.
Общий `insufficient_quota` не доказывает, что закончился именно баланс:
причина уточняется по `code`.

## Путь ошибки

- `AssistantAgent.stream_response_events()` выбирает сообщение и публикует его
  в существующем `RequestFinishedEvent.error_message`.
- Ошибка при создании зависимостей или до терминального события обрабатывается
  тем же способом в `SequenceRenderer.render_response()`.
- `ResponseExecution.fail()` сохраняет выбранный текст и остаётся идемпотентным:
  уже полученный терминальный результат не заменяется общей ошибкой.
- Текущий alert и повторное отображение истории читают одинаковый
  `ExecutionSnapshot.error_message`.
- Этапы закрываются один раз, управление разблокируется. Уже подтверждённый
  вариант остаётся в истории и доступен для Save; неудачный Regenerate сохраняет
  исходную карточку. Следующий запрос может завершиться успешно после пополнения.

Публичная история содержит фиксированный текст и ссылку. Провайдерский payload,
stack trace, ключи и внутренние идентификаторы в неё не копируются.
Изменение не добавляет запросов к API или собственных автоматических повторов;
настройки повторов SDK остаются прежними.

## Проверка

Офлайн-проверки используют настоящие исключения SDK и подкласс LangChain:
точный код исчерпания, общий quota, обычный rate limit, неизвестные и неполные
ответы, другие HTTP-статусы, цепочки исключений. Повторный `fail()` проверяется
после локального завершения и после полученного терминального события:
сообщение, подтверждённый вариант и закрытые этапы не меняются.
Поток агента проверяется на отказ до инструментов
и при подготовке финального ответа после commit. AppTest проверяет чат,
Generate, Regenerate, создание зависимостей, сохранение истории и следующий
успешный запрос без платных вызовов.

Источник контракта:
[официальная документация OpenAI — Error codes](https://developers.openai.com/api/docs/guides/error-codes).

## Результат — 2026-10-12

Фича реализована. Общий классификатор подключён к потоку агента и к ранним
ошибкам рендерера. Существующие события и снимки хранят выбранное сообщение;
новые поля протокола не потребовались.

- `.venv/bin/python -m unittest discover -s tests -p 'test_api_credit_errors.py' -v`
  — **15 тестов, OK**.
- `.venv/bin/python -m unittest discover -s tests` — **276 тестов, OK**.
- `git diff --check` — без ошибок.

AppTest выполняет настоящий Streamlit entrypoint и цикл агента с подставной
моделью. Проверены отсутствие вызова генерации при отказе модели, сохранение
сообщения без повторного model call при rerun, восстановление следующим запросом,
история неудачного Regenerate, исходная карточка и Save, а также commit/Save
при исчерпании кредитов перед финальным ответом. Платные API не вызывались.

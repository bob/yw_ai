# Приёмка профилей GPT — фича 011

Связанный документ: [README](README.md).

## 1. Routing и payload

1. Generate и Regenerate выбирают `generation`, независимо от слов в
   исходном запросе. Поиск первой позы доступен; gallery и edits недоступны.
2. Простые ru/en команды выбирают ожидаемый узкий профиль. Routing не вызывает
   GPT, Jev, каталог или генератор. Полный user request сохраняется.
3. «Добавь две и поменяй местами первую/третью», «покажи кандидатов, не меняй»,
   «что будет, если добавить», неизвестная формулировка и отдельный вопрос
   выбирают `general`; неподдержанное действие не имитируется.
4. Перехват actual model request показывает только разрешённые schemas.
   Общее ядро и инструкции профиля присутствуют; посторонние инструкции
   отсутствуют. Профиль и порядок tools не меняются внутри одного запроса.
5. Вызов tool вне профиля не проходит к сервису. Следующий пользовательский
   запрос может выбрать другой профиль в том же thread.
6. Локальные статические размеры укладываются в цели README; отчёт включает
   baseline 3704 и итоговую таблицу каждого профиля.

## 2. Подтверждения и количество вызовов

7. Успешные простые Generate/add/swap/replace получают один финальный ответ
   с фактическими count/позициями/именами, без вызова GPT для подтверждения.
   При необходимости поиска промежуточные GPT calls остаются.
8. Generate 9 → «Добавь 3 асаны» даёт 2 обычных GPT calls суммарно вместо 4,
   без изменения inputs/count Jev. Все полные snapshots и Save payloads совпадают.
9. Длительность с bilateral и cap, add с усечением, `no_change`, повтор имени
   и stale UUID не получают выдуманного числа или успеха. Когда структурированных
   фактов недостаточно, финальный ответ выполняет GPT.
10. Шаблонный ответ сохраняется в canonical messages и execution history;
    после rerun появляется один раз, без повторного tool/model call.
11. Сложный general запрос и другой язык сохраняют ответ GPT. Уточнение и
    исправление ошибки до commit остаются возможными.
12. Catalog search не превращается в автоматическое display. Простой browsing
    подтверждается только после успешного show; ошибка/пустая выборка не
    объявляется показанной галереей.

## 3. Регрессии

Проверить старый выбранный вариант, positions/UUIDs, cap 45, default count,
duration, явную первую позу, одну операцию, последовательные tools, атомарное
добавление, ошибки API, прогресс и browser-independent Save payloads.
Успех commit и финальный текст имеют прежний порядок. Публичные ответы
не содержат внутренний профиль, cache key или имена middleware.

Offline fixtures используют scripted model с перехватом tools/system/messages
и fake generator/catalog/TypeSafe. Семантику сокращённого prompt проверять
дополнительно репрезентативным ru/en диалогом на GPT с fake подбором, без
Jev API. Отдельно фиксировать, какие этапы действительно выполнены.

Сравнить входные/выходные токены и model-call counts по профилям. После
реализации записать команды, результаты и ограничения в README.

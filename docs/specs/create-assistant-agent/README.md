## Выполненный этап: пункты 1–3

`AssistantAgent` и `AssistantAgentError` заменили прежние имена в сервисах,
фабрике, UI и тестах. Четыре tools объявлены в пакете `tools/` и зарегистрированы
у одного `create_agent`; генерация остаётся в `SequenceGenerator`.
Добавлены фильтры поиска и `CatalogTagService`. Язык фиксируется HTTP-клиентами,
не входит в аргументы tools; имена каталога не преобразуются. Модель получает
результаты tools и завершает ответ на языке пользователя; текст отображается
и сохраняется в чате. Generate/Regenerate сохраняют прежний интерфейс генерации
и default 9 элементов, если число и длительность не указаны.

На этапе пунктов 1–3 `replace_sequence_element` был зарегистрирован с
согласованными аргументами и адаптером обработчика приложения. Пункт 5
подключает проверяемую замену непосредственно к состоянию tools; выполненный
сценарий описан ниже.

Настройка модели: непустой `ASSISTANT_AGENT_MODEL` → непустой
`SEQUENCE_AGENT_MODEL` → `openai:gpt-5.5`. `.env.example` использует новое имя.
Entrypoint приложения переименован в `src/langchain_app/assistant.py`.
Проверка: `uv run python -m unittest discover -s tests -v` — 38 тестов без
платных API-вызовов, включая HTTP-контракты и Streamlit Generate/Regenerate.

## Выполненный этап: контекст секвенции (пункты 4 и 6)

`GeneratedSequence` хранит полный материализованный состав: catalog items,
позиции, UUID вхождений и mirror flags. Генерация публикует `Command` с полным
снимком, активным UUID и структурированным `ToolMessage`. `AssistantState`
объединяет варианты по UUID; старые снимки не изменяются.

Middleware `selected_sequence_context` перед каждым вызовом модели добавляет
выбранный снимок, включая исходный запрос, IDs/UUIDs, tags, bilateral и порядок.
Image URLs остаются в состоянии и результате tool, но исключены из текущей
проекции prompt. Если варианта нет, передаётся `selected_sequence: null`.
Актуальная проекция имеет приоритет над старыми tool messages; она не добавляется
в сохраняемую историю сообщений.

`AssistantAgent` создаётся лениво и хранится в текущей `st.session_state` вместе
со своим `InMemorySaver` и неизменным thread ID. Между запросами сохраняется
история human/AI/tool messages. Общий кеш содержит только сервисы, а не диалог.
Карточки хранят UUID вариантов; прежние поля views остаются совместимыми
проекциями и восстанавливаются из полного состояния на rerun.

Previous/Next и «Use this sequence» меняют активный UUID без модели и генератора;
обычный rerun и отрисовка других карточек не меняют выбор. Regenerate использует
исходный запрос и family выбранной карточки, сохраняет parent UUID и создаёт
новые вхождения. Save получает UUID и mirror flags того же снимка.

Ошибка во время генерации не сохраняет частичный вариант. Успешный commit
сохраняется даже при ошибке последующего текстового ответа модели. Старые
карточки только с thumbnails остаются доступными для просмотра; автоматическое
восстановление catalog items для них пока не подключено.

Проверка: `uv run python -m unittest discover -s tests -v` — 50 тестов без
платных API-вызовов, включая каждый model call, смену выбранного варианта,
Regenerate старой карточки, ошибки, reruns и изоляцию двух Streamlit-сессий.

## Выполненный этап: замена и история вариантов (пункт 5)

`replace_sequence_element` читает выбранный снимок из состояния агента и
проверяет UUID варианта, UUID вхождения и ID кандидата из последней выборки
`search_catalog_items`. Поиск сохраняет проверенные items в `latest_catalog_items`;
следующий поиск заменяет выборку, пустой или неуспешный поиск её очищает.
Middleware очищает кандидатов и при ошибке валидации аргументов поиска.

Детерминированный editor создаёт глубокую копию с новым UUID, прежней family,
`parent_uuid` выбранного варианта и `operation=replace`. Сохраняются исходный
запрос генерации, метаданные, порядок и UUID всех вхождений. Меняются только
catalog item выбранного вхождения и его mirror flags, установленные по bilateral.
Новый снимок и активный UUID записываются одним `Command`; исходный снимок
не изменяется. Генератор при замене не вызывается.

Устаревший UUID, неизвестное вхождение, непроверенный кандидат, отсутствие
image URL/catalog UUID и повтор другой асаны возвращают ошибку без нового
варианта. Сравнение catalog items использует ID или UUID без учёта регистра.
Замена на себя возвращает `no_change` и сохраняет прежний UUID.
Tools выполняются последовательно; пакет одновременных вызовов отклоняется.
После успешного изменения второй commit в том же запросе запрещён.

Результат замены появляется в новой карточке с историей всей family, выбранным
новым вариантом и навигацией Previous/Next. Save использует UUID и flags
выбранного снимка. Regenerate этой карточки повторяет исходный запрос генерации,
а не текст замены. Rerun восстанавливает проекции; ошибка текстового ответа
модели после commit не теряет новый вариант.

Проверка: `uv run python -m unittest discover -s tests -q` — 65 тестов без
платных API-вызовов, включая замену в выбранной старой family, проверки ошибок,
историю, Save, Regenerate, rerun и ошибку ответа после успешного commit.
Типизированные stream-события с `request_id` и восстановление полного контекста
legacy-карточек остаются отдельными расширениями спецификации.

## Выполненный этап: границы редактирования (пункт 7)

В первом этапе поддерживается замена одного элемента за пользовательский
запрос. Поиск и получение тегов могут предшествовать замене; после успешного
изменения второй commit отклоняется, даже если модель использует актуальный
UUID нового варианта. В следующем пользовательском запросе замена снова
доступна. При просьбе заменить несколько элементов агент сначала уточняет,
какой один элемент изменить.

Добавление, удаление, перемещение и самостоятельное изменение зеркальности
не зарегистрированы как tools. Агент объясняет, что эти операции пока
недоступны, и не подменяет их генерацией или заменой. Их предварительные
контракты описаны как [последующее расширение](sequence-context.md#9-другие-операции-последующий-этап);
точный состав можно изменить на ревью. Установка mirror flags нового catalog
item по bilateral при замене остаётся частью текущей операции.

Проверка: `uv run python -m unittest discover -s tests -q` — 66 тестов без
платных API-вызовов. Дополнительный сценарий проверяет запрет второй замены
другого вхождения с актуальным UUID и успешную замену в следующем запросе
с сохранением обоих предыдущих вариантов.

## Основания

Контракт Asana Catalog берётся из локальных документов:

- [Поиск catalog items](../../public_catalog_items_search.md).
- [Получение имён catalog tags](../../public_catalog_tag_names.md).
- [Импорт сгенерированной секвенции](../../import_generated.md).

Документация API допускает `en`, `uk`, `ru`, но требование этой интеграции —
всегда `en`. Ни новые endpoints, ни изменения Asana Catalog для первого этапа
не требуются.

## Порядок реализации первого этапа

1. Расширить HTTP-клиент поиска, добавить клиент тегов и проверить API-контракты.
2. Выделить общий агент и tools, сохранить прежнее поведение генератора.
3. Добавить состояние диалога, события и отображение текстовых ответов в UI.
4. Подключить выбранную секвенцию к контексту и реализовать замену элемента.
5. Проверить историю вариантов, Regenerate, Save и изоляцию пользовательских
   сессий. Обновить README и `.env.example` под итоговые имена.

Каждая спецификация содержит критерии приёмки для соответствующего этапа.

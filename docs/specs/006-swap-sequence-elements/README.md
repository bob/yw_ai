# 006 — Обмен двух элементов секвенции местами

Статус: **реализовано; пункты 1–6 плана выполнены, приёмка пройдена**.

Добавить инструмент `swap_sequence_elements`: по просьбе пользователя он
меняет местами два существующих вхождения в выбранной секвенции и создаёт
новый вариант. Например, «Поменяй третью и пятую асаны местами» превращает
`[A, B, C, D, E]` в `[A, B, E, D, C]`.

Операция использует полный снимок выбранного варианта и существующий механизм
истории, активного контекста, прогресса и Save. Она дополняет
`replace_sequence_element`; поиск каталога, генератор и TypeSafe для самого
обмена не требуются.

## 1. Сценарии и разрешение ссылок

Поддерживаемые запросы:

- «Поменяй третью и пятую асаны местами».
- «Поменяй первую и последнюю позы».
- «Поменяй местами Tree pose и Mountain pose», если каждое имя однозначно
  определяет вхождение в выбранном варианте.
- Выбор старого варианта через Previous/Next или Use this sequence, затем
  обмен элементов именно этого варианта.

Ассистент разрешает обе ссылки по актуальному `selected_sequence` перед
вызовом инструмента. Позиции начинаются с 1, «последняя» означает позицию `N`.
Имена служат для выбора вхождения из снимка; результат поиска каталога
не определяет, какое вхождение нужно переставить. При нескольких совпадениях
имени, неоднозначном местоимении или указании только одного элемента
ассистент уточняет недостающую позицию до изменения.

Если указанной позиции нет или не выбрана секвенция с полным снимком,
ассистент объясняет проблему. Он не создаёт новую секвенцию автоматически.
Вопрос «Что изменится, если поменять третью и пятую местами?» требует
объяснения; обмен применяется при просьбе выполнить действие, включая
«Можешь поменять третью и пятую местами?». Для однозначной команды
на обмен дополнительное подтверждение не требуется.

## 2. Контракт `swap_sequence_elements`

Аргументы, видимые модели:

| Аргумент | Тип | Назначение |
| --- | --- | --- |
| `sequence_uuid` | UUID-строка | UUID выбранного варианта |
| `first_element_id` | UUID-строка | Первое вхождение из актуального снимка |
| `second_element_id` | UUID-строка | Второе вхождение из актуального снимка |

Позиции, catalog IDs и объекты элементов не принимаются вместо этих UUID.
`ToolRuntime` предоставляет состояние и контекст запроса, как у существующей
замены, и не является аргументом модели. Оба `element_id` должны принадлежать
одному выбранному варианту.

Порядок проверок согласован с `replace_sequence_element`:

1. При `require_generation=true` вернуть `generation_required`: команды
   Generate и Regenerate должны выполнять генерацию.
2. При `generation_started=true` или `turn_operation_committed=true` вернуть
   `operation_already_started`.
3. Прочитать полный активный снимок из `sequences[active_sequence_uuid]`;
   если его нет, вернуть `sequence_not_found`.
4. Сверить `sequence_uuid` с UUID активного снимка; несовпадение возвращает
   `stale_sequence`, даже если переданный вариант сохранился в истории.
5. Проверить наличие обоих вхождений; неизвестный UUID возвращает
   `sequence_element_not_found`. Проверить оба UUID до создания копии.
6. Если оба аргумента указывают на одно существующее вхождение, вернуть
   `status=no_change` и UUID исходного варианта без изменения состояния.
7. Создать и атомарно зафиксировать новый вариант по правилам ниже.

Невалидный формат UUID отклоняется стандартной валидацией аргументов tools.
Ожидаемые ошибки возвращаются через существующий `tool_error` с
`status=error`, `code`, `message` и правильным `tool_call_id`.
Ошибки и `no_change` не создают UUID варианта, не меняют активный выбор
и не расходуют возможность успешного изменения в этом запросе.

## 3. Семантика обмена и вариант

Переставляются целые `GeneratedSequenceElement`. `element_id` следует за
вхождением, а не остаётся привязанным к позиции. Вместе с ним перемещаются
полный `catalog_item`, `start_mirror` и `end_mirror`. Зеркальность сохраняется
точно, включая значения, отличающиеся от `catalog_item.bilateral`;
пересчитывать её при обмене нельзя.

В новом списке два выбранных вхождения занимают прежние позиции друг друга.
Элементы между ними сохраняют свои позиции. После перестановки `order`
соответствует фактическому порядку списка и составляет `1..N`.
Обмен соседних элементов, крайних элементов и секвенции из двух элементов
подчиняется тому же правилу.

| Поле нового варианта | Правило |
| --- | --- |
| `uuid` | Новый UUID |
| `family_uuid` | Сохраняется из выбранного варианта |
| `parent_uuid` | UUID выбранного варианта |
| `operation` | `swap` |
| `operation_request` | Полный текущий запрос пользователя |
| `generation_request` | Сохраняется исходный запрос генерации |
| `name`, `description`, `language` | Сохраняются |
| `elements_count` | Не меняется; вычисляется из списка |

Расширить допустимые значения `GeneratedSequence.operation` значением `swap`.
Прежние снимки `generate`, `regenerate` и `replace` продолжают читаться.
Исходный снимок и остальные варианты остаются неизменными; новый вариант
создаётся глубокой копией, без общих изменяемых объектов с родителем.

Разные вхождения одного catalog item тоже можно обменять: их идентичность
и mirror flags могут различаться. Такой обмен создаёт вариант, даже если
изображения визуально одинаковы. Проверки кандидатов и запрет дубликатов
из операции замены сюда не переносятся: состав каталожных элементов
не меняется. `latest_catalog_items` не читается и не обновляется.

Правила подбора стартовой, второй и завершающей поз относятся к генерации.
Явный обмен выполняется и для этих поз без повторного подбора или проверки
переходов через TypeSafe. Дополнительный лимит числа элементов не вводится.

## 4. Фиксация и результат инструмента

Сервис `swap_elements` в `services/sequence_editor.py` принимает исходную
`GeneratedSequence`, два UUID вхождений и текст запроса. Он возвращает
новый `GeneratedSequence` либо `None` для `no_change` и использует
`SequenceEditorError` для неизвестного вхождения. Работа с состоянием
агента остаётся в инструменте.

При успешном обмене инструмент возвращает один `Command`, который:

- добавляет полный снимок в `sequences` с существующим merge-reducer;
- устанавливает `active_sequence_uuid` в UUID нового варианта;
- устанавливает `turn_operation_committed=true`;
- добавляет компактный `ToolMessage` с `status=ok`, UUID, `operation=swap`,
  `elements_count` и описанием обмена по [контракту 009](../009-compact-gpt-tool-results/tool-contract.md).

Поле `swap` в результате — список из двух записей в порядке аргументов:

```json
[
  {"element_id": "<first_element_id>", "name": "<имя первой позы>", "old_order": 3, "new_order": 5},
  {"element_id": "<second_element_id>", "name": "<имя второй позы>", "old_order": 5, "new_order": 3}
]
```

Имена и позиции берутся из исходного и нового снимков. Полный новый снимок
доступен в `state.sequences` и следующем `selected_sequence`, без дублирования
в тексте tool result. Для `no_change` результат
содержит только `status=no_change` и `uuid` исходного варианта.
После commit следующий вызов модели получает обновлённый выбранный снимок.
Ассистент отвечает на языке пользователя и кратко сообщает, какие две позы
и позиции поменял местами. Для `no_change` объясняет, что указано одно
и то же вхождение.

Один обмен считается **одной операцией изменения секвенции**, хотя затрагивает
два элемента. Действует общий лимит: максимум одно успешное создание или
изменение секвенции за пользовательский запрос. Второй обмен, замена после
обмена, обмен после замены или генерации отклоняются с
`operation_already_started`, в том числе с актуальным UUID нового варианта.
В начале следующего запроса лимит сбрасывается существующим механизмом.
Для просьбы выполнить несколько обменов или обмен и замену ассистент
уточняет, какую одну операцию выполнить первой.

## 5. Прогресс, отображение и Save

Зарегистрировать tool в `ASSISTANT_TOOLS` и обновить системную инструкцию:
редактирование поддерживает замену одного элемента либо обмен одной пары.
Перемещение одного элемента на произвольную позицию со сдвигом остальных,
добавление, удаление и отдельное изменение зеркальности остаются следующими
фичами. Обмен нельзя имитировать двумя заменами или Regenerate.

В `response_progress_middleware.TOOL_STEPS` сопоставить новый инструмент
существующему коду `updating_sequence` с заголовком
`Swapping sequence elements...`. Добавить отдельные summaries для успешного
обмена и `no_change`; существующий текст `Sequence element replaced.`
и сообщение о кандидате, который уже присутствует, не подходят для обмена.

Использовать существующее подтверждение commit: `sequence_committed` появляется
один раз после того, как новый полный снимок доступен в состоянии агента.
У события корректные `request_id`, `step_id`, `tool_call_id` и UUID варианта.
Обмен не публикует предварительные `sequence_element` или
`catalog_items_displayed`. Ошибка и `no_change` завершают этап соответствующим
outcome без `sequence_committed`.

Чат показывает новый вариант существующей карточкой секвенции с историей
family, Previous/Next, Use this sequence, Regenerate и Save. Новые кнопки
для обмена или drag-and-drop в эту фичу не входят. При `no_change` или ошибке
новая карточка секвенции не создаётся.

Миниатюры и импортный JSON строятся из нового снимка: порядок и mirror flags
соответствуют перемещённым вхождениям, Save использует новый `info.uuid`
и реальные catalog UUID. Повторный Save сохраняет UUID выбранного варианта.
Regenerate использует исходный `generation_request` и автоматически обмен
не повторяет. Rerun восстанавливает результат без повторного вызова tools;
ошибка финального текста модели после commit сохраняет вариант и Save.
